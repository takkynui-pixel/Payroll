# VTA Payroll

ระบบ Payroll & Outsourcing แบบหลายบริษัท (multi-tenant) ของ VTA Service
Next.js (Vercel) + Supabase (Postgres, Auth, Storage) ทุกการเข้าถึงข้อมูลผ่านสิทธิ์ของผู้ใช้ที่ล็อกอิน + RLS
**ไม่ใช้ `service_role` key ในโปรเจกต์นี้**

## พอร์ทัลและบทบาท

| พอร์ทัล | เส้นทาง | บทบาท | ทำอะไรได้ |
|---|---|---|---|
| ทีม Payroll | `/admin` | `super_admin`, `payroll_admin` | ดูบริษัท/พนักงาน, สร้างงวด, คำนวณ, ส่งให้ลูกค้าตรวจ, ปิดงวด |
| จัดการสิทธิ์ | `/admin/users` | `super_admin` เท่านั้น | ให้บทบาท/ระงับ/ถอนสิทธิ์, ผูกบัญชีกับพนักงาน (บัญชีล็อกอินสร้างที่ Supabase Dashboard) |
| ลูกค้า | `/client` | `client_hr` | ตรวจผลคำนวณ, อนุมัติหรือส่งกลับพร้อมเหตุผล |
| พนักงาน | `/payslips` | `employee` | ดู/พิมพ์สลิปของตัวเอง (เฉพาะงวดที่อนุมัติแล้ว) |

ขั้นตอนของงวด: `draft → calculated → client_reviewing → approved → closed`
ฐานข้อมูลบังคับลำดับและสิทธิ์ผ่านฟังก์ชัน `change_payroll_period_status()` (หน้าเว็บแค่ซ่อน/แสดงปุ่ม)

## โครงสร้าง

```
app/                      หน้าจอและ Server Actions
  (auth)/login            เข้าสู่ระบบ
  (admin)/admin/...       พอร์ทัลทีม Payroll
  (client)/client/...     พอร์ทัลลูกค้า
  (employee)/payslips/... สลิปเงินเดือน
lib/payroll/service.ts    โหลดข้อมูลงวด -> engine -> บันทึกผล (atomic)
lib/payroll/mapping.ts    แปลงข้อมูลดิบจาก DB เป็น input ของ engine (ฟังก์ชันล้วน)
supabase/functions/_shared/payroll/   engine คำนวณ (ฟังก์ชันล้วน ไม่แตะ DB, ใช้ได้ทั้ง Node และ Deno)
supabase/migrations/      SQL ตามลำดับ 001 -> 002 -> 003 -> 004 -> 005
tests/                    vitest (engine, mapping, workflow)
proxy.ts                  รีเฟรช session และส่งผู้ที่ยังไม่ล็อกอินไป /login (Next 16 ใช้ชื่อ proxy แทน middleware)
```

## ฐานข้อมูล (Supabase project: Payroll-VTA)

รัน migration ตามลำดับ **ใน SQL Editor** (001 และ 002 ถูกรันไปแล้วบนโปรเจกต์นี้):

1. `001_payroll_core.sql` — ตาราง, RLS, audit, ล็อกงวด, เข้ารหัสเลขบัตร
2. `002_storage.sql` — bucket `payslips` / `imports` และ policy
3. `003_tax_profiles_and_save_results.sql` — **ยังไม่ได้ยืนยันว่ารันแล้ว** เพิ่มตาราง `employee_tax_profiles`, ฟังก์ชัน `save_payroll_results` (บันทึกผลทั้งงวดใน transaction เดียว) และเพดานลดหย่อนประกันสังคม

> อย่าใช้ `supabase db push` กับโปรเจกต์นี้โดยไม่ซ่อมประวัติ migration ก่อน (`supabase migration repair`) เพราะ 001/002 ถูกรันด้วยมือและ CLI จะพยายามรันซ้ำ

4. `004_member_management.sql` — ฟังก์ชันสำหรับหน้า `/admin/users` (`list_access`, `add_member`, `set_member_active`, `remove_member`, `link_employee_account`, `unlink_employee_account`) รันซ้ำได้
5. `005_employee_and_timesheet_rpc.sql` — `create_employees`, `change_salary`, `import_timesheets` (security invoker: ใช้สิทธิ์ผู้เรียก + RLS, บันทึกทั้งชุดหรือไม่บันทึกเลย) รันซ้ำได้

หลังรัน 003, 004 และ 005 ให้ generate types ใหม่ (`types/database.ts` ตอนนี้มีส่วน `[PENDING 003]` / `[PENDING 004]` / `[PENDING 005]` ที่เขียนด้วยมือ):

```bash
npx supabase gen types typescript --project-id jmddftqdpctymfliutot > types/database.ts
```

ก่อนใช้งานจริง:
- กุญแจเข้ารหัสเลขบัตร `id_card_key` ใน Vault (มีแล้ว ห้ามสร้างทับ ไม่งั้นเลขบัตรที่เข้ารหัสไว้ถอดไม่ได้)
- `super_admin` คนแรกในตาราง `company_members`
- เปิด Leaked password protection และ MFA ใน Supabase Auth

## Deploy บน Vercel

## วิธีคำนวณและสมมติฐาน (ให้นักบัญชี/ผู้รู้ภาษีตรวจก่อนใช้งานจริง)

อัตราและเพดานทั้งหมดอ่านจากตาราง `statutory_rates` / `tax_brackets` ตามวันที่มีผล ไม่ฝังในโค้ด

- **รายเดือน:** ค่าจ้างรายวัน = เงินเดือน ÷ 30, รายชั่วโมง = รายวัน ÷ 8
- **OT:** รายชั่วโมง × ชั่วโมง × ตัวคูณ (1.0 / 1.5 / 2.0 / 2.5 / 3.0) ปัดเป็นสตางค์ทีละรายการ
- **ประกันสังคม:** ฐาน = ค่าจ้างหลังหักขาด/สาย + รายรับที่ติด `is_ss_base` (ไม่รวม OT) จำกัดระหว่างขั้นต่ำ/ขั้นสูง คูณอัตรา
- **ภาษีหัก ณ ที่จ่าย:** `normal` = ประมาณการทั้งปีแบบสะสม (ยอดสะสมที่ผ่านมา + รายได้งวดนี้ × งวดที่เหลือ) แล้วหักภาษีที่หักไปแล้ว หารงวดที่เหลือ
  `calculate_per_month` = รายได้งวดนี้ × จำนวนงวดต่อปี คิดภาษีแล้วหาร `no_tax` = ไม่หัก
- ทุกค่าที่ใช้คำนวณถูกเก็บใน `payroll_results.input_snapshot` ตรวจย้อนหลังได้

### ข้อที่ยังต้องยืนยัน

1. **การปัดเศษเงินสมทบประกันสังคม:** ค่าเริ่มต้นปัดเป็นบาทเต็ม (`ssRounding: "baht"`) ตามไฟล์นำส่ง สปส. จริงที่ตรวจเทียบแล้ว 69 แถว (เดือน ก.ย. 2026) มีตัวเลือกปัดเป็นสตางค์ แต่ยังไม่ผูกกับการตั้งค่าบริษัท ควรให้ผู้ทำบัญชียืนยันอีกครั้ง
2. **เพดานลดหย่อนเงินสมทบประกันสังคมในการคำนวณภาษี (`tax_ss_deduction_cap` = 9,000):** เป็นค่าเดิมจากบทความ ยังไม่ยืนยันกับกรมสรรพากร (เพดานเงินสมทบเพิ่มเป็น 875 บาท/เดือนในปี 2569)
3. **อัตราและขั้นภาษีที่ seed ไว้** มาจากบทความที่อ้างข้อมูลกรมสรรพากร ไม่ได้เปิดเอกสารต้นทางโดยตรง

### ข้อจำกัดปัจจุบัน

- เริ่มงาน/ลาออก/ปรับเงินเดือนกลางงวด: พนักงานรายเดือนคิดตามสัดส่วนวันทำงานจริง (ฐาน 30 วัน) ระบบแจ้งรายชื่อตอนคำนวณ รายวัน/รายชั่วโมงจ่ายตามวันทำงานในไฟล์เวลา
- ภาษีรองรับรอบจ่ายรายเดือนและครึ่งเดือนเท่านั้น
- กองทุนสำรองเลี้ยงชีพ (PVD) ถูกหักจากเงินสุทธิแต่ **ยังไม่ลดฐานภาษี** ค่าลดหย่อนอื่นต่อปีใส่ผ่าน `employee_tax_profiles`
- โบนัสหรือรายได้ครั้งเดียวถูกประมาณการเป็นรายได้ประจำที่เหลือทั้งปี ภาษีจึงอาจหักมากในงวดนั้นแล้วถูกปรับลดในงวดถัดไป (รวมทั้งปีถูกต้อง)
- **นำเข้า Excel (`/admin/import`)** ใช้แม่แบบมาตรฐานที่ดาวน์โหลดจากระบบ 2 แบบ: (1) เวลาทำงาน + รายการเพิ่ม-หักของงวด (2) พนักงานใหม่พร้อมเงินเดือน ตรวจไฟล์ก่อนบันทึก ถ้ามีแถวผิดไม่บันทึกเลย ยังไม่รองรับสมุดงานของลูกค้าโดยตรง (เช่นไฟล์ ERNI) ต้องแปลงเป็นแม่แบบก่อน
- **พนักงาน:** เพิ่มทีละคน แก้ข้อมูล ปรับเงินเดือน (เก็บประวัติ) ที่ `/admin/employees`
- **ยังไม่มี:** สลิป PDF, ไฟล์โอนเงินธนาคาร, ไฟล์นำส่งประกันสังคม, ใบ 50 ทวิ (PDF รายคน) และไฟล์อัปโหลด ภ.ง.ด. ของสรรพากร


## ภ.ง.ด.1 / ภ.ง.ด.1ก

เมนู **ภ.ง.ด.** (`/admin/tax`): เลือกบริษัท ปี และเดือน แล้วเปิดตัวอย่างแบบฟอร์ม พิมพ์หรือบันทึกเป็น PDF จากหน้าต่างพิมพ์ของเบราว์เซอร์

- ใช้ผลคำนวณของงวดที่ **อนุมัติแล้วหรือปิดงวด** เท่านั้น เงินได้ = รายได้รวมของงวด ภาษี = ภาษีที่หักในงวด (หน่วยสตางค์ ไม่มีเศษ float)
- ภ.ง.ด.1: 1 แถวต่อพนักงานต่อวันที่จ่าย ตัวเลือก "รวมพนักงานที่ภาษี 0" เปิดไว้ตามแบบที่ยื่นจริงในไฟล์ตัวอย่าง
- ภ.ง.ด.1ก: รวมทั้งปีต่อคน รวมคนที่ภาษี 0 ต้องมีที่อยู่พนักงาน (กรอกที่หน้าข้อมูลพนักงาน)
- ข้อมูลหัวแบบ (สาขา ที่อยู่ ผู้ลงนาม) กรอกที่ บริษัทลูกค้า > ชื่อบริษัท (ต้องรัน migration 007)
- แบบ กท.20 ก (กองทุนเงินทดแทน) ต้องรัน migration 008 และกรอกเลขที่บัญชีนายจ้าง รหัสกิจการ อัตราเงินสมทบ ที่หน้าเดียวกัน
- เวลาทำงานเก็บเป็นนาที ต้องรัน migration 009 (หลัง 006) แม่แบบนำเข้าเวลาทำงานเป็นแบบ ID Emp + Day/Hr/min ตามไฟล์จากระบบเวลา ค่ากะ/ค่ากินเป็นรายได้ที่เสียภาษีแต่ไม่เป็นฐานประกันสังคม
- การเปิดแบบถอดรหัสเลขบัตรประชาชน ฐานข้อมูลบันทึกใน audit log ทุกครั้ง
- ใบแนบพิมพ์หมุนบนกระดาษ A4 แนวตั้ง (เหมือนแบบที่ยื่นจริง) เพราะเบราว์เซอร์พิมพ์หน้าต่างขนาดในไฟล์เดียวไม่ได้
- ยังไม่มีไฟล์สำหรับยื่นออนไลน์ (RD Prep/อัปโหลด) ต้องใช้สเปกไฟล์จากกรมสรรพากร
